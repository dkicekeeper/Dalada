# M29. Веб-страницы «Поделиться»

> 2026-10-06. Из плана ([05-cross-cutting.md](../02-plan/05-cross-cutting.md#шаринг-и-рост), 1.1):
> «Лёгкая веб-версия места, поездки, улова с превью в Telegram — чтобы видели друзья с Android и без
> приложения». Сборка 137.

## Что делает

- «Поделиться» у **публичного места** даёт ссылку `…/Dalada/p/<id>/`: в браузере — название, тип,
  описание, фото редакции, карта (у приблизительного — круг), «Маршрут» (у точного),
  «Открыть в Dalada» и «Как попасть в бету». В Telegram — **превью** с названием, описанием и фото.
- У **публичной поездки** — «Ссылка на поездку» в меню «…» и ссылка в сообщении к картинке:
  `…/s/?trip=<id>` — цифры, автор, трек на карте (как у гостя: без начала и конца).
- У **публичного улова** — ссылка в сообщении к картинке: `…/s/?catch=<id>` — вид, размер (если не
  скрыт), дата, место (если публичное), фото.
- Закрытое, удалённое, чужая ссылка — «Запись недоступна» и «Откройте ссылку в приложении».
- **Приглашение в друзья** (1.0.1) — `…/s/?u=<ник>`: «Вас зовут в Dalada», пара слов о приложении,
  App Store и «Открыть профиль в Dalada». Без запросов к базе: страница знает только ник из ссылки,
  поэтому ничего не раскрывает о закрытом профиле.
- Язык страницы — по языку браузера (RU / KK / EN).

**Для поиска (1.0.1, [план продвижения](../05-release/promotion.md)):** страницы мест — с заголовком
под запрос («Рыбалка: Озеро Талы — отчёты, фото, запреты»), описанием по типу места, если своего нет,
названием и описанием в HTML до скрипта и `canonical`; все они, главная и пресс-страница — в `sitemap.xml`
(`…/Dalada/sitemap.xml`, отдаём поисковикам через Search Console). Страницы поездок, уловов и
приглашений — `noindex`: это записи людей, искать их через Google не нужно. Заголовок статической
страницы места скрипт не переписывает.

**Метки кампаний:** если задана переменная репозитория `APP_STORE_PT` (токен поставщика из App Store
Connect), ссылки на App Store идут с `ct`: `site` (главная), `site-place`, `site-share` (поездка, улов),
`trip-invite`, `invite`. Переменная `GOOGLE_SITE_VERIFICATION` добавляет на главную метатег Search
Console.

**Для прессы:** `press.html` (RU / KK / EN) — факты, иконка `press/icon.png`, контакт; ссылка на App
Store с меткой `press` (`{{APP_STORE_URL:press}}` в HTML — так любая страница сайта задаёт свою метку).

## Почему так

Сайт — GitHub Pages (статический), а Supabase отдаёт HTML только со своим доменом. Поэтому:

- страницы **мест** собираются заранее (раз в день и при изменении сайта) — у них настоящее превью;
  новое публичное место получит превью со следующей сборки, а до неё ссылка открывает ту же
  страницу через `404.html`;
- поездки и уловы — одна страница, данные грузит браузер; превью в Telegram — общее (Dalada).

Своё превью у поездок и уловов будет, когда появится свой домен (Cloudflare Worker или свой домен
у Supabase) — тогда же универсальные ссылки, открывающие приложение сразу.

## Приватность

Только публичное и то, что видит гость в приложении: RPC `web_places`, `web_trip`, `web_catch`
(ключ гостя). Найти поездку или улов можно только по ссылке (UUID), списков нет. Текст из базы
страница вставляет только как текст — разметка в названиях не выполняется. Адрес Supabase и
публичный ключ гостя попадают на сайт из секретов при сборке (в репозитории их нет).

## Как устроено

- `20261118100000_web_share.sql`: `web_places()`, `web_trip(id)`, `web_catch(id)` для гостя.
- Сайт: `docs/public/s/` (шаблон, `share.js`, `share.css`, `og.png`), сборка —
  `.github/scripts/build_site.py`, публикация — `pages.yml` (по изменениям и раз в день).
- iOS: `WebLink`; «Поделиться» места, «Ссылка на поездку», сообщения к картинкам.
- Тесты: pgTAP `52_web_share` (12), `ShareCardsTests`; страницу проверял в Chromium на локальной базе.
