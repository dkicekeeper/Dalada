## Коротко

1. **Мест много, а рассказать о них нечего.** 1403 места редакции — все из OpenStreetMap: точка и
   название. Описание есть у 8 % (содержательное, от 150 знаков, — у 1 %), фото — у 2 %, какая рыба,
   как подъехать и как ловить — до этой волны ни у одного места. Пользовательских отчётов пока нет,
   так что карточку места наполняет только редакция.
2. **Начинаем с того, что видно.** 131 место в шести подборках «Мест», затем водоёмы у Алматы, где
   больше всего людей, затем крупные водоёмы по стране. Волна — 12–50 мест, каждая — отдельным PR.
3. **Только проверяемые факты со ссылкой на источник.** Факты (размеры, глубины, рыба, ледостав)
   берём из Википедии, научных работ и официальных документов, текст пишем сами; источник каждой
   строки — в `place_info.csv`. Если источника нет, поле остаётся пустым — лучше пусто, чем выдумано.
4. **Первая волна сделана:** 12 мест подборки «Подлёдная рыбалка» к событию «Первый лёд» — описания,
   виды рыб, способы ловли, размеры и глубины — и статья «Подлёдная рыбалка: с чего начать». Для этого `places.py` научился собирать атрибуты мест
   из новой таблицы `place_info.csv`, а страница места на сайте показывает описание целиком (раньше —
   первые 200 знаков).
5. **Фото — через GitHub.** Из облачного контейнера API Wikimedia Commons отвечает 429, поэтому
   кандидатов ищет новый workflow **Photo candidates** на раннере GitHub; 1289 мест ещё ни разу не
   искали.
6. **Дальше:** подборки (119 мест), фото, водоёмы и реки, которых нет на карте, чистка (солёные
   озёра, одинаковые названия, латиница), справочник рыб (17 → ~35 видов), статьи к сезону.

### Фото

- 97 фото у 32 мест, все с Wikimedia Commons под свободными лицензиями (автор и лицензия — под фото в
  приложении).
- Кандидатов искали у 114 мест: 97 взяты, 557 отклонены (не то место, мутные, люди крупным планом).
  1289 мест не искали ни разу.
- API Commons отвечает 429 на запросы из облачного контейнера Claude (превью с `upload.wikimedia.org`
  при этом качаются) — поиск перенесён на раннер GitHub, см. [процесс](#фото).
- Снимки с МКС («ISS043-E-…», «View of Earth») геометкой попадают «рядом» с местом, а на них облака и
  ночная Земля, — `photos.py` их больше не предлагает. Спутниковые снимки (Sentinel-2, MODIS, Landsat)
  — тоже: вид сверху и так есть на карте.
- Поиск по всем местам без фото прошёл к 2026-11-09. Ещё один источник — сам элемент Wikidata, на
  который ссылается OSM: изображение (P18) и категория Commons (P373). Они не геометкой «рядом», поэтому
  первый проход их не находил; у 151 места без фото есть ссылка на Wikidata.
- На Commons по Казахстану мало фото малых озёр. Первая партия поиска (2026-11-09, 300 водоёмов):
  кандидаты нашлись у 46, а подходящие фото — только у 5 (Жасыбай, Арасан, Кокколь, Большой
  Талдыколь, Садовское — 10 фото). Остальное — улицы, птицы, грибы и даже туманности, снятые рядом.
  Значит, со всех 1106 водоёмов Commons даст ещё 15–25 мест; больше шансов у достопримечательностей,
  стоянок, родников и баз. Реалистично с Commons — около 120 мест с фото; дальше — фото из отчётов
  людей (после модерации) и свои снимки редакции.

## Процесс

### Описание места

`description` в `places.csv`, по-русски, 150–600 знаков (поле в базе — одно, без переводов):

1. Где: область и район, ближайший город или село, как добраться (трасса, сколько км от города).
2. Что за вода: водохранилище или озеро, на какой реке, пресное ли.
3. Что ловится — по источнику; виды, которых нет в справочнике (налим, язь), — только в тексте.
4. Сезон: ледостав, когда открыто; особенность или опасность (ветер, волна, неоднородный лёд).

Без «лучшее место», без цен и телефонов без даты, без советов, которые нельзя проверить. Если про
рыбу источника нет — так и пишем и просим рассказать в отчёте.

### Сведения места

`supabase/data/places/place_info.csv` — то, что приложение показывает в блоке «Сведения» (ключи —
как в `DaladaCore/PlaceInfo.swift`, проверка — как у базы, `private.place_attributes_valid`):

| Колонка | Что | Значения |
|---------|-----|----------|
| `id`, `name` | Место — как в `places.csv` (название сверяется) | |
| `species` | Какая рыба | id из `fish_species` через «;» |
| `access` | Подъезд | `asphalt`, `dirt`, `offroad`, `foot`, `boat` |
| `fee`, `price_kzt`, `price_unit`, `contact` | Платно ли, цена и за что, контакт (до 100 знаков) | `free` / `paid`; `entry`, `day`, `hour`, `kg` |
| `methods` | Как ловят | `shore`, `boat`, `spinning`, `feeder`, `float`, `fly`, `bottom`, `ice` |
| `amenities` | Удобства | `parking`, `toilet`, `shade`, `tent`, `fireplace`, `drinking_water`, `shop`, `boat_rental` |
| `signal` | Связь | `none`, `weak`, `good` |
| `months` | Лучшие месяцы | 1–12 через «;» |
| `features` | Особенности: размеры, глубины, дно, течение | до 1000 знаков |
| `sources` | **Обязательно**: откуда сведения | ссылки через «;» |

Подъезд, удобства, связь и лучшие месяцы ставим только с источником (сайт базы, отчёты, свой выезд) —
по энциклопедии их не узнать.

### Фото

1. Actions → **Photo candidates** → Run workflow на рабочей ветке (на `main` не запускается): пусто в
   `places` — места без фото, которые ещё не искали (сначала достопримечательности, стоянки, базы и
   родники, водоёмы — в конце), до `limit` за запуск; или id мест через запятую. Workflow коммитит
   `photo_candidates.csv` и `photo_searched.txt` в ту же ветку.
2. `git pull`, затем `python3 supabase/data/places/photos.py sheets /tmp/sheets` — листы превью.
3. В `photo_candidates.csv`: `include` — 1, 2, 3… (1 — обложка) или `no`. Берём: само место, светлое,
   без людей крупным планом и без водяных знаков; не больше 5 на место.
4. `photos.py accept` → `photos.py migration` → PR. Файлы на R2 кладёт **Editorial photos** после
   слияния.

### Проверка и выкатка

```bash
python3 supabase/data/places/places.py migration && python3 supabase/data/places/places.py check
python3 supabase/data/places/photos.py check
supabase db reset && supabase test db
```

PR с волной — по-русски, со списком мест и источников; после слияния миграцию применяет
GitHub-интеграция Supabase, места обновляются в приложении сразу.
